# Step 2: Discussion guide

A guide for a 60 to 75 minute session with 3 to 6 participants, or a 45 minute one-to-one. Adapt freely; the sections follow the toolkit's loop so findings land on the right building block.

```
The person → Ability profile → Adapter → Validation → back to the person
```

Share these questions with participants ahead of time. Times are approximate.

## Private response options

Every section offers a way to answer that the rest of the group cannot see. Explain these at the start, and use them in every section, not only for sensitive topics.

This comes from my work on CRS's ReMiND project in India, where a shared language of shapes and colors let participants answer privately without needing to read. For remote sessions:

| Option | How it works |
|---|---|
| Direct message | Participant sends a private chat message to the facilitator |
| Color code | Participants hold up or type a color: green "this works for me", yellow "not sure / sometimes", red "this doesn't work for me" |
| Private form | A short accessible form, open during and for two days after the session |
| One-to-one follow-up | A paid 15 minute call for anything a participant would rather say privately |

Color codes are always paired with a word, so they work for people who cannot see color.

## 0. Welcome and consent (10 min)

- Introductions: name or nickname only, and the device and tools each person is using today
- Read the key consent points aloud; confirm each person's three consent answers
- Explain the private response options
- Remind everyone: there are no right answers, and we are testing the toolkit, not them

## 1. Your setup today (10 min)

*Warm-up. Gives context for everything that follows.*

- What do you change or turn on when you start using a new app or website?
- What do you wish you didn't have to set up again every time?
- Tell us about a time an app or site got it right for you. What did it do?

## 2. Ability profile: what should be remembered (15 min)

*Informs what the profile records, and what people will and won't share.*

- If an app could remember one thing about how you like to use it, what would it be?
- Is there anything you would never want an app to remember or share with another app?
- Who should hold this information: you, each app separately, or a service you choose? Why?
- How would you want to see or change what has been remembered about you?

**Private response round:** green / yellow / red on "I'd be comfortable with my preferences following me from one app to the next."

## 3. Adapter: changes to the interface (15 min)

*Informs which adaptations matter most and how they should be offered.*

If possible, show two or three adaptations live (for example, using the toolkit's example browser extension on a test page). Otherwise, describe them.

- What did you notice? What helped, and what got in the way?
- Would you want this change to happen automatically, be suggested, or only happen when you ask?
- What change is missing that you would want first?

**Private response round:** green / yellow / red for each adaptation shown.

## 4. Validation: when an AI should stop and ask (15 min)

*Informs where the Validation agent should pause, and how it should ask.*

Walk through one or two short scenarios. Example:

> "You've asked an AI assistant to renew a subscription for you. It finds a cheaper plan that removes a feature you use. What should it do?"

- At what point should it stop and check with you?
- How should it ask: a message, a sound, a pause, something else?
- When an app changes something for you, how would you like it to check that the change didn't break anything you rely on?
- Has a tool ever made a decision for you that you wish it had asked about first?

## 5. What's missing (5 min)

- If you could change one thing about this toolkit before anyone else uses it, what would it be?
- Anything you'd like to tell us privately? (Remind them of the private form and one-to-one follow-up.)

## 6. Close (5 min)

- Explain what happens next: we will write up what we heard, check it back with you, and then turn it into tasks
- Confirm the payment date
- Confirm how they would like to receive the check-back summary (email, audio, plain-language document, call)

## Facilitator notes

- Two people run each session: one facilitates, one takes notes and watches the private channels
- Note needs in participants' own words where consent allows; never record diagnoses, even if mentioned
- Tag notes live with the building block they relate to: `[P]` profile, `[A]` adapter, `[V]` validation, `[X]` other
